# LLM Review Output Contract

## Write boundary

The LLM must not directly update these authoritative tables:

- `filing`
- `filing_document`
- `filing_section`
- `filing_table`
- `xbrl_fact`
- `form13f_holding`
- `evidence_snippet`
- existing deterministic `semantic_assertion` rows

The reviewer emits append-only JSONL records to a staging file. A separate validator or human approval step may later promote an approved correction.

Recommended staging path:

```text
data/sec_yfinance/reviews/<run_id>/<batch_id>.jsonl
```

## One-record rule

Each line represents one atomic review decision for one primary evidence item and, where applicable, one reviewed assertion.

Do not return markdown around JSONL. Do not combine several predicates into one record.

## Allowed enums

### `action`

```text
accept
reject
supersede
create_candidate
no_change
taxonomy_candidate
```

### `claim_class`

```text
reported_fact
management_estimate
risk_hypothesis
policy_or_rule
management_interpretation
third_party_statement
reviewer_inference
```

### `explicitness`

```text
explicit
attributed
inferred
```

### `status`

LLM-created records must always be:

```text
review_required
```

The LLM is not authorized to emit `accepted` as a database status, even when `action = accept`. `action = accept` means it recommends retaining the deterministic claim.

### `source_available_at_precision`

```text
datetime
date
derived
```

### `delta_class`

```text
new
removed
intensified
de_intensified
unchanged
wording_only
not_comparable
null
```

## Field rules

### Identity

- `security_id`, `issuer_id`, `filing_id`, accession, and symbol must match the primary evidence row.
- The reviewer must not normalize identity by guessing.
- Anonymous entities remain anonymous stable keys.

### Evidence

- `primary_evidence_id` is mandatory.
- `corroborating_evidence_ids` may contain only governed evidence supplied within the PIT boundary.
- Do not paste or rewrite the evidence snippet into the output; reference the stored evidence ID.
- `source_available_at` must exactly match the governed evidence record and must not be generated by the LLM.

### Timing

- `source_available_at <= signal_timestamp` is mandatory.
- Date-precision evidence is invalid for intraday review.
- `effective_from` may describe an earlier economic period, but it never changes source availability.
- `created_at` is review creation time, not evidence availability.

### Actions

- `accept`: requires `reviewed_assertion_id`; predicate and object should normally match the reviewed assertion.
- `reject`: requires `reviewed_assertion_id` and a concrete rejection reason.
- `supersede`: requires `reviewed_assertion_id` and a complete corrected atomic claim.
- `create_candidate`: requires no reviewed assertion, but needs a supported predicate/object.
- `no_change`: predicate and object may be null; rationale must state why evidence is insufficient.
- `taxonomy_candidate`: object must contain proposed label, definition, parent, aliases, and collision notes.

### Confidence

- Confidence is numeric in `[0, 1]`.
- It measures evidence-to-semantics support, not future economic truth.
- New inferred claims below `0.50` are prohibited; use `no_change`.

### Rationale

- Maximum 600 characters.
- Explain the semantic decision, not investment implications.
- Do not cite future outcomes.
- Do not claim the source is true merely because it was filed with the SEC.

### Limitations

Use short machine-readable labels, for example:

```text
anonymous_counterparty
management_claim_unverified
scope_ambiguous
period_not_comparable
external_corroboration_missing
relation_direction_uncertain
unit_or_scale_uncertain
```

## Supersession policy

A correction never edits or deletes the original assertion.

A promotion process should create:

1. a review record linked to the original assertion;
2. a new candidate assertion linked to the same evidence or additional eligible evidence;
3. a supersession edge or status change applied at review/approval time;
4. preserved original `available_at`, extractor ID, and extractor version.

Historical queries as of a time before correction must still be able to reproduce the original knowledge state and extraction state.

## Validation gate

Reject the entire batch when any of these is non-zero:

```text
missing_primary_evidence
unknown_evidence_id
identity_mismatch
source_time_mismatch
evidence_after_signal_timestamp
intraday_date_precision_use
invalid_enum
accepted_status_emitted
missing_model_identity
missing_prompt_hash
multi_claim_record
future_outcome_reference
source_evidence_mutation
```

Individual records with resolvable semantic uncertainty may be retained as `no_change`; governance violations must fail the batch.
